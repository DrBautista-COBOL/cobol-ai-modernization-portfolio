🧩 Concise takeaway
CBACT04C reads transaction category balances, groups them by account, retrieves account + disclosure data, computes monthly interest and fees, writes transaction records, and finally updates the account master balance.
📁 Program purpose and high‑level flow
The program is a batch job that:

1. Reads TCATBAL (Transaction Category Balance) records sequentially.
2. For each account:
   * Loads account master data
   * Loads cross‑reference (card ↔ account) data
   * Loads disclosure group (interest rate) data
3. Computes:
   * Monthly interest
   * Fees (via a separate routine)
4. Writes a transaction record to TRANSACT
5. Updates the account master balance
6. Continues until end‑of‑file

This is typical mainframe batch processing: read → enrich → compute → write → update.

Each file has a specific role:

* TCATBAL — Transaction category balances
* XREF — Card ↔ customer ↔ account cross‑reference
* ACCOUNT — Account master record
* DISCGRP — Disclosure group (interest rate table)
* TRANSACT — Output transaction file (interest postings)

All files use FILE STATUS fields for error handling.
🏗️ Major working‑storage structures
Key variables:

* WS-MONTHLY-INT — computed interest for one category
* WS-TOTAL-INT — accumulated interest for the account
* WS-LAST-ACCT-NUM — detects account boundary changes
* WS-TRANID-SUFFIX — increments for each transaction written
* APPL-RESULT / APPL-AOK / APPL-EOF — status codes
* COBOL-TS / DB2-FORMAT-TS — timestamp formatting fields

🔄 Main loop logic
The core loop:

1. Read next TCATBAL record
2. If account changes:
   * Write accumulated interest to ACCOUNT file
   * Reset totals
   * Load ACCOUNT + XREF data
3. Load disclosure group
4. Compute interest
5. Write interest transaction
6. Continue until EOF

This is a classic "control break" pattern.
💰 Interest calculation logic
The interest formula:
WS-MONTHLY-INT=TRAN-CAT-BAL⋅DIS-INT-RATE1200
Then:

* Add to WS-TOTAL-INT
* Write a transaction record (type 01, category 05)

🧾 Account update logic
When finishing an account:

* Add WS-TOTAL-INT to ACCT-CURR-BAL
* Zero out cycle credit/debit fields
* REWRITE the account record

🛠️ Error handling
Every file operation checks:

* Status "00" → OK
* Status "10" → EOF
* Status "23" → record not found (DISCGRP defaulting)
* Anything else → ABEND

Errors call:

* 9910-DISPLAY-IO-STATUS
* 9999-ABEND-PROGRAM

🧠 Non‑obvious insights

* The program does not compute interest per transaction — it computes interest per transaction category balance, which is already aggregated.
* The disclosure group lookup uses three keys: account group, transaction type, and category.
* When DISCGRP returns status "23", the program automatically switches to a DEFAULT disclosure group.
* Transaction IDs are built using:
   * The PARM-DATE passed to the program
   * A numeric suffix
This ensures uniqueness without needing a DB2 sequence.
